# Data contracts

JSON Schemas (draft 2020-12) are generated by `pipelines/contracts.py` into `data/contracts/*.schema.json`, one per published artifact in `site/public/data/`.
Every artifact has `schema_version: "v1"`, `generated_at` (= latest raw retrieval time from the manifest, so reruns are byte-identical), and `tags` (field group ->
OBSERVED | DERIVED | SYNTHETIC | SIMULATED, joined by `/`). Each artifact is under 400 KB gzip (enforced by `pipelines/validate_artifacts.py`).

## Artifacts
| Artifact | Contents | Main tags |
|---|---|---|
| `meta.json` | sources with hashes, attribution, sizes, limitations, file list | OBSERVED sources |
| `quality.json` | join ledger (counts at every filter), selection summary, executed generator checks | OBSERVED/DERIVED |
| `network.json` | commodities, 100 demand nodes, 16 candidate sites, 3 plants, out-arc list, plant-to-site distances, generator constants | place fields OBSERVED, rest SYNTHETIC |
| `model.json` | formulation, LP text layout rules, solver options, penalties, controls[], presets, sizes | SYNTHETIC |
| `solutions.json` | precomputed scenario solutions: status, objective, components, routes, binding constraints, duals, relaxation reports | SYNTHETIC |
| `robustness.json` | seeded Monte Carlo config, per-draw disruption descriptors and outcomes, summaries, histograms, site criticality | SYNTHETIC/SIMULATED |
| `solver_test_vectors.json` | browser parity vectors: generator inputs (params), LP text SHA-256, status, objective; one full LP text | SYNTHETIC |
| `facts.json` | every headline number used in copy (single source of truth) | mixed |

## Units and conventions
Distance: road-equivalent miles = round(great-circle miles x 1.2, 1 decimal). Demand: tons per year. Capacity: throughput units per year
(`units = tons x capacity_units_per_ton`; cold chain uses 1.6 units per ton). Costs: USD per year (fixed), USD per ton-mile (rates), USD per ton (handling).
Indices are zero-based: site f, demand node d, plant p, commodity k (0 ambient, 1 cold, 2 bulk), out-arc a. Out-arc `a` links `out_arcs.site[a]` to `out_arcs.demand[a]`.

## PRECOMPUTED fallback contract
`solutions.json` holds one solution per preset id from `model.json.presets`. The site shows `PRECOMPUTED · PYTHON HiGHS` for these and `SOLVED IN BROWSER · HiGHS` for live
solves. If the worker or wasm fails, the UI falls back to the preset with the same `params` (exact match) and says so; free-form control values with no matching preset
have no fallback, the UI must show the error with a retry.

## LP text (browser parity)
Both implementations build the identical text:
1. Coefficients: every coefficient is rounded with `r4(x) = floor(x * 10000 + 0.5) / 10000` (half up). Formed products: `demand = r4(tons * demand_scale)`,
   `fixed = r4(fixed_cost * fixed_cost_scale)`, `cap = r4(capacity_units * capacity_scale)`, `t_out = r4(rate_out * road_mi * freight_scale)`,
   `t_in = r4(rate_in * road_mi * freight_scale)`, `handling = r4(handling)`. The objective coefficient of an out-arc column is `t_out + handling` (sum of two rounded numbers, then formatted).
2. Formatting: `fmt(v)` = fixed 4 decimals, trailing zeros and a dangling point stripped, `-0` written `0`. No exponent notation anywhere.
3. Column order (`model.json.lp_format.column_order`): z, x, y, then (relaxed only) u, so, sp, sm. Row order: dem, flw, cap, sup, lnk, mxo, cls, fix. Objective lists non-zero costs in column order.
4. Sections: `Minimize`, `Subject To`, `Bounds` (closed lanes `x = 0`), `Binary` (all z), `End`.
5. `lp_text_sha256` = SHA-256 of the UTF-8 text. Columns of a solved model must be mapped back **by name**: HiGHS orders file columns by first appearance, not by the published order.
Solver options are published in `model.json.solver.options` and are part of the contract: `mip_rel_gap = 0`, `mip_abs_gap = 1e-6`, `threads = 1`, `random_seed = 0`.

## Parity vector rules
Parity keys: `lp_text_sha256`, `status`, `objective_usd` (relative tolerance 1e-6). `components`, `open_sites`, `relaxed_groups` are informative (alternative optima and
degenerate slack splits can differ between solver builds). The status strings are pinned: `Optimal`, `Infeasible`.

## Route precision
`routes_out = [arc, commodity, tons]` and `routes_in = [plant, site, commodity, tons]` are the solved flows rounded to 3 decimals (tons), flows below 0.0005 omitted.
Recomputing demand balance from routes alone matches to 0.01 t per (node, commodity); recomputing the objective from routes matches to 1e-5 relative.

## Honesty tags
OBSERVED: population, internal-point coordinates. DERIVED: road-equivalent distances. SYNTHETIC: all generated and solved quantities. SIMULATED: Monte Carlo draws and outcomes.
